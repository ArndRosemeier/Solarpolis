# Working on Solarpolis

Solarpolis is a detailed 3D simulation set about 1000 years from now, starting inside a mature O'Neill cylinder in Earth orbit (TypeScript, three.js on WebGPU, Vite). The vision and Arnd's decisions are in [docs/design/README.md](docs/design/README.md), the whole setting in his [world bible](docs/world-bible.md). Read them before starting anything.

1. **Nothing about the habitat is hardcoded.** The cylinder is a parametric blueprint (`src/blueprint`) that will later fill the whole solar system. Every size, rate and count comes from `HabitatParams` through `derive()`. Figures like 8 × 30 km are example values. Every geometry test runs over the whole `MATRIX` (small, reference, large, long), so a hidden constant fails there.
2. **Read [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (the seam index) before writing any helper.** Use the one way it names. A new seam gets its row in the same PR. Rows marked *planned* name the seam to build; do not invent a different one.
3. **WebGPU only, no fallbacks** (Arnd, 2026-10-21). No `forceWebGL`, no WebGL context (guarded). A browser without WebGPU gets a clear message, not a degraded game.
4. **Shaders follow [docs/SHADERS.md](docs/SHADERS.md):** materials only from the material registry, things enter the scene through `stage.add`, no `onBeforeCompile`, no `renderer.compile*` outside the Stage. 100 ms per build is the hard limit.
5. **No `Math.random`, no wall clock in the simulation.** Every random number comes from a seed (`Rng`, `deriveSeed` from `@futuremagic/core`). The population is derived from seed + clock; only people the player touches are simulated in detail.
6. **Pure layers stay pure.** `src/blueprint` (and later `src/gen`, `src/world`, `src/sim`) never import three or the DOM (guarded), so they run in workers and headless tests.
7. **Shortcuts only for performance.** Arnd: performance matters, but so does feeling different. Never simplify the physics or the look just to save work.
8. **Every PR description has a `COPIES:` line**: `COPIES: 1 — checked (grepped: ...)` or `COPIES: 3→1 — <seam>`.
9. **`npm test` must be green.** It runs the guards (banned patterns, layer boundaries, the duplication ratchet). A `NEW` finding means fold the copy into one seam, or add it to `tools/guards/duplication-baseline.json` with a reason.
10. **CI has a hard 2-minute cap** ([docs/CI.md](docs/CI.md)). Each test, file and the whole suite has a budget in `tools/ci/budget.json`; only the suite's total fails CI, a test or file over its own budget is a warning to fix in the same PR. A slow test is made faster or moved to `test/slow/` (`npm run test:slow`); the cap is never raised without Arnd.
11. **Each PR adds a change note** `changes/<slug>.md` (see [changes/README.md](changes/README.md)). Never edit `CHANGELOG.md`; a workflow folds the notes after the merge into the next version (v0.001, +0.001 per merge), which the What's new button shows.
12. **Memory is watched from the start.** Anything holding big buffers reports them with `memory.track(owner, bytes)` and gives memory back through `memory.onPressure(level, shed)` (`src/app/memory.ts`). iPads are a target, and Safari kills a tab long before the device runs out of RAM. Memory discipline is strict (Arnd, 2026-10-21: we need a lot of headroom for what is coming): every cache has a byte budget (`StreamCache` `maxBytes`), nothing keeps a CPU copy of what the GPU holds (`dropUploaded`), a mesh is given up only through `freeMesh`, and a feature that adds memory checks who holds the heap on the render PC (view `memory-inside`, `scripts/shots/heap.mjs`) and says the figure in its PR.
13. **The mouse pointer is always visible and free** (Arnd, 2026-10-21): no pointer lock. The left button clicks things in the world; holding the right button looks around (one-finger drag on touch screens).
14. **Developer tools go in the one debug menu** (Shift+Ctrl+F12, `debug.add` / `debug.addInfo`, made in `src/main.ts`). No thread adds its own debug key or overlay.
15. **Merge your own PRs.** Arnd does not do Git: the thread that opens a PR squash-merges it as soon as CI is green and review findings are handled. When main has moved, bring it in first and let CI run again.
16. **Never take a LOD level away before its replacement is built and drawn** (Arnd, 2026-10-21: "never remove a LOD before the real thing is there"). Every swap between levels (plants, grass, stones, ground tiles, hull detail, landmarks, ships, anything new) keeps the old level on screen until the new one is uploaded, then hands over, and the levels match in size, colour and silhouette. Use the seams in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) ("How does one level of detail hand over…"), never a swap by distance alone. The debug menu's `plant LOD` line counts holes; it must stay 0 (shots view `walk-meadow`).
17. **Porting from Dunfinity, SimWorld or Scale:** take the code with its tests, adapt the names, and note the source file in the header comment.

Shared packages come from the AssetGenerator submodule (`vendor/assetgenerator/packages`: `@futuremagic/core`). Clone with `--recurse-submodules`, or run `git submodule update --init`. Humanoid robot bodies and people will come from Arnd's Actors package.

Checks that need a browser: the cloud container's headless Chromium draws WebGPU in software (SwiftShader), takes minutes a frame and loses the device after a few. Look at frames on real WebGPU instead: Arnd's PC renders any pushed branch with `npm run shots` ([scripts/shots/README.md](scripts/shots/README.md)), checks every WGSL module and WebGPU error, and pushes the pictures and a report to the `renders` branch. Ask for a render by pushing `HEAD:refs/heads/shots-req/<who>/<view,view>`; add the views you need to `scripts/shots/views.mjs` in your branch. Arnd's PC is the reference for how it really looks and runs.
